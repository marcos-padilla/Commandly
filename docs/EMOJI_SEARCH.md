# Emoji Search

Emoji Search replaces only the old Offline Tools emoji application registration. Its existing application ID `tools.emoji-search` and open-tool ID `tools.emoji-search.tool.open` remain stable. `tools.emoji-search.ai` opens the separate AI mode without submitting anything. Other offline tools and all Productivity Library `emojiKeyword` items retain their existing behavior and persistence.

## Catalog and data provenance

The app bundles every **Unicode 17.0 RGI emoji sequence**: 3,944 fully-qualified entries plus 9 components. These yield 1,923 default family entries, with exact skin-tone variants available in the native picker or full grid. A further 1,272 official minimally/unqualified spellings resolve to canonical presentation. The data preserves variation selectors, ZWJ combinations, regional and subdivision flags, gendered/neutral combinations, and mixed tones. Names/categories come from Unicode emoji-test; English keyword annotations come from CLDR. Native `Text` renders the exact sequence using macOS fonts. No competitor/vendor glyph assets are bundled; font support determines appearance on each OS release.

Pinned primary sources:

- [Unicode 17.0 emoji-test data](https://www.unicode.org/Public/17.0.0/emoji/emoji-test.txt), including its RGI status definitions and count summary.
- [CLDR 48 release](https://cldr.unicode.org/downloads/cldr-48), updated for Unicode 17. English [annotations](https://github.com/unicode-org/cldr/blob/release-48/common/annotations/en.xml) and [derived annotations](https://github.com/unicode-org/cldr/blob/release-48/common/annotationsDerived/en.xml) are pinned. Both files were verified byte-identical to release-48-2; the later 48.2.1 patch lists CLDR JSON changes. CLDR 49 was still alpha at the review date (2026-09-14), so no development-branch data is used.
- [Unicode License V3](https://www.unicode.org/license.txt), SPDX `Unicode-3.0`. The full copyright and permission notice accompanies both vendored source data and the bundled generated JSON. Unicode data/CLDR are data inputs, not a third-party runtime/package dependency.

`python3 scripts/generate-emoji-catalog.py --check` verifies the SHA-256-pinned source files, exact source counts, unique sequences, all family targets, and byte-for-byte reproduction of the bundled JSON. Run without `--check` to regenerate. This uses only Python's standard library and makes no network requests. Each input URL/hash is recorded in the generated document. The input license is `scripts/emoji-data/UNICODE-LICENSE.txt`; the distributed copy is `Commandly/Resources/Emoji/UNICODE-LICENSE.txt`.

## Ownership and behavior

`Services/Emoji` owns the immutable validated catalog, actor-based resource loading/search, the AI adapter, and injectable services. `Commands/Emoji` owns the native grid/detail view and its MainActor model. The application is registered separately so the legacy curated `EmojiCatalog` and unrelated Offline Tools logic need no drive-by changes.

The bundled 1 MB JSON is loaded/indexed lazily on an actor when Emoji Search opens; it does not add launch/root-search I/O. Searches check cancellation every 64 entries and return the complete matching set, with lazy grid rendering. Normalized English names, keywords, categories, and subgroups support case/diacritic-insensitive token matching. Exact names/whole terms rank ahead of partial words, then stable source order. Category selection remains effective for pasted exact symbols. Tone words reveal variants without synthesizing new combinations. Complete data remains accessible through Show all skin tones. No automatic clipboard reads occur.

The six-column grid keeps Up/Down aligned with rows. With grid focus, Left/Right move one cell; in the search field they retain native text-editing behavior. Explicit Copy Emoji, Return, or Command–Shift–C writes the exact selected sequence using the injected pasteboard. Choosing an emoji or variant only selects it. Return during a local query defers one copy until that query completes; query edits, route changes, or Escape invalidate it. Copy coalesces rapid repeated Return while work is pending. In-flight AI has an inert primary action so a second Return cannot cancel or duplicate a provider request. Escape first cancels AI, then clears a description, then lets the launcher return home. Native controls remain keyboard reachable; each cell has its official name and selected state, and the selected-detail accessibility subtree changes identity with the selected sequence. App text-size controls apply to labels; codepoint strings and the full name can be selected as text.

## Optional genuine AI search

`ProviderEmojiSemanticSearch` uses the existing `QuickAIServicing` provider runtime, credential/connection revision checks, and text-only request transport. On explicit Find with AI it sends one original format instruction and only the user's description, using the displayed saved provider/model. No tools, clipboard, files, contacts, library data, or prior searches are supplied. Existing transport endpoint/authentication/privacy boundaries remain authoritative. Reading saved choices is metadata-only; remote model discovery is not invoked. AI Settings and Refresh Saved AI Connections provide recovery.

Descriptions are bounded to 1,024 UTF-8 bytes. Stream callbacks only count bytes and reject more than 8 KiB; no partial response is displayed. The final result must be a completed assistant text response containing a JSON array of at most 12 exact catalog strings. Official qualification aliases normalize to canonical emoji, duplicates coalesce in order, and any invalid element rejects the entire response. No guessed extraction from prose, untrusted URLs, or AI-generated labels are displayed. Empty valid arrays show a clear no-results state. Errors are sanitized and never echo response bodies/credentials. Local synonyms are never labeled as AI. Models can still produce semantically poor but syntactically valid suggestions; users review and explicitly copy.

Query/provider/mode changes and teardown cancel requests and invalidate generation identifiers; noncooperative late responses are ignored. Session input/results are not persisted, uploaded implicitly, or logged. Explicit copying uses normal Clipboard History behavior if the user enabled it. A clipboard write already performed cannot be revoked by subsequent cancellation.
